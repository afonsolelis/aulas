Part 1

Four words

Language model, harness, agent and skill describe four different things. Knowing which one you are dealing with explains most of what an AI tool gets right and most of what it gets wrong.

Part 1 · 1 of 4 · Large language model

A large language model predicts the next piece of text

An LLM is a neural network trained on a very large amount of text to estimate which piece of text, called a token, is most likely to come next.

1

Training

The model reads books, websites and code and adjusts billions of numbers, called weights, until it predicts the next token well. Training ends at a cutoff date, so the model does not know what happened after it.

2

Use

When you write a message, the weights no longer change. The model reads everything in its context, which is your message plus whatever the app adds, and writes the answer one token at a time.

3

Consequence

The model chooses the most likely text, which is not always the true text. It writes a wrong answer with the same confidence as a right one, so the quality of the answer depends on what you put in the context and on someone checking it.

ChatGPT, Gemini and Claude are apps built on top of models such as GPT, Gemini and Claude. The next slide shows the model alone, and slide 8 shows what the app adds around it.
Part 1 · 1 of 4 · Large language model

Token by token, with and without the syllabus

At each step the model reads the whole context, passes it through its layers of weights and gets a probability for every possible next token. The course, the syllabus and the values are illustrative.

1 · Tokens2 · Weights3 · Probabilities4 · Choice
Model · layers of weights

Billions of weights, set during training and fixed during use. For every token, the whole context goes through every layer.

Next token · probability

The model calculates which continuation is most likely and does not check whether it is true. The answer improves when the right document is in the context, and a person still has to check what comes out. Apps also measure context limits and plan usage in tokens.
Part 1 · 2 of 4 · Harness

The harness is the software around the model

The model only receives text and returns text. Everything else you see in an AI app, from file uploads to web search, is done by the harness, which decides what goes into the context and what happens with the answer.

The same model behaves differently in different harnesses, because each one fills the context in its own way. When two AI tools disagree, the cause is often the harness and not the model.

Part 1 · 3 of 4 · Agent

An agent thinks, acts and observes

An agent is a model that the harness lets use tools in a loop. The model decides what is missing, calls a tool, reads the result and decides the next step, and the model itself chooses the order and the number of turns.

How much is a dinner in São Paulo today, in euros?

thinkWhat does an average dinner cost there? actsearch("average dinner price São Paulo") observeabout R$ 80 per person thinkNow I need today's exchange rate. actsearch("euro to real exchange rate today") observe€ 1 = R$ 6.10 thinkOnly the conversion is left. actcalculate(80 / 6.10) observe13.11

About €13 per person.

Without the loop, the model would answer from memory, with a price and a rate that may be old or invented. With tools, the search brings today's data and the calculator does the arithmetic. Price and rate are illustrative. Adapted from the deck Primeiros passos by Prof. Nicola.
Part 1 · 4 of 4 · Skill

A skill is a procedure loaded when it is needed

Until a skill is called, the model sees only its name and a one-line description. You call it by name, or the model calls it when the description matches your request, and then the harness adds the full text to the context.

Part 2

Prompt engineering with CREATE

A prompt is everything you tell the model about the task. CREATE is a checklist of six parts that a good prompt usually has, proposed by Dave Birss for writing with generative AI.

Time
10:25 – 10:35
Example
A study guide from class notes
Part 2 · Why prompts fail

A short prompt leaves the decisions to the model

Both prompts below ask for the same thing about the same class notes. The first one makes the model guess the audience, the format and the limits, and the guesses change every time.

Short prompt 
Summarize my notes.
  • The model does not know who will read the summary or what it is for.
  • Length and format change from one answer to the next.
  • Gaps in the notes are filled with general knowledge, without warning.
  • The Portuguese terms from class may disappear or be translated in different ways.
CREATE prompt 
You are a teaching assistant for exchange students.
Write a study guide of the attached class notes.
[a sample glossary row and a sample question]
Use only the notes; list what they do not explain.
Five sections: summary, key ideas, PT→EN glossary,
five questions with answers, check with professor.
Ask if I want flashcards at the end.
  • Each line settles one decision the model would otherwise make alone.
  • The answer has the same structure every time, so it can be checked quickly.
Part 2 · The method

The six parts of a CREATE prompt

Not every prompt needs all six parts, but going through the list before writing shows which decisions are still missing.

C

Character

The role the model should take, with the experience and the point of view you expect.

R

Request

The task itself, with a clear verb and the object of the task.

E

Examples

One or more samples of the expected result, which show the pattern better than a description.

A

Adjustments

Rules and limits, such as which sources to use, what not to do and the tone.

T

Type of output

The format of the answer, such as a table, a list, an email or a text of a given length.

E

Extras

Further instructions, such as asking questions before answering or pointing out what needs review.

The Adjustments part carries most of the protection against invented answers. A rule such as "use only the attached notes and list what they do not explain" tells the model what to do when information is missing.

From a prompt to a skill

Part 3 · The skill format

A skill is a file with a name, a description and a procedure

The format comes from Agent Skills, the open standard used by Claude: a folder with a file called SKILL.md. The header tells the harness when to load the skill, and the body is the CREATE prompt itself.

---
name: study-guide
description: Turns the notes, transcript or slides of
  one class into a one-page study guide in English, with
  a Portuguese–English glossary and five self-check
  questions. Use when the user shares material from a
  lecture and asks to study, review or prepare for a test.
---

# Study guide from lecture material
C## Character       teaching assistant for exchange students
R## Request         a study guide for one class
E## Examples        one glossary row, one question
A## Adjustments     only the material; no graded work
T## Type of output  exactly five sections
E## Extras          your language; offer flashcards

The description decides when it runs

The harness reads only the name and the description until the skill is needed. A description that says what the skill does and when to use it lets the model pick it without being asked.

The same text works in three places

  • In Gemini, the body goes into the instructions of a Gem.
  • In Claude, it goes into the instructions of a project.
  • In Claude, the whole folder can also be uploaded as a skill, where your plan allows it.
Part 3 · Two ways to install it

Installing the skill as a Gem or as a Claude project

Choose one platform. In both, the instructions stay saved and apply to every chat you start inside the Gem or the project.

Google Gemini · Gem

  1. Open gemini.google.com and choose Explore Gems, then New Gem.
  2. Name it Study guide.
  3. In Instructions, paste the text of SKILL.md from # Study guide to the end.
  4. In Knowledge, you can add files the Gem should always read, such as the course syllabus.
  5. Save, open the Gem and attach sample-lecture-notes.txt to the first message.

Claude · Project

  1. Open claude.ai, choose Projects and then Create project.
  2. Name it Study guide and add a one-line description.
  3. In Instructions, paste the text of SKILL.md from # Study guide to the end.
  4. In Files, you can add documents every chat should read, such as the syllabus.
  5. Start a chat inside the project and attach sample-lecture-notes.txt.
If Projects or Gems does not appear in your account, paste the same text at the start of a normal chat. The guide will be the same, but you will have to paste the instructions again in every new chat.

Wrap-up · 10:55 – 11:00

Limits to keep in mind

The same mechanism that makes the study guide useful explains where it can go wrong.

1

Plausible is not correct

The model writes the most likely text. Check names, numbers, dates and citations against the source before you study from the guide or share it.

2

Your data leaves your device

What you paste or upload is processed by the provider. Read the privacy settings of your account and keep other people's personal data out of the chat.

3

Each course sets its rules

Universities and teachers have different policies on AI in graded work. Using the guide to study is one thing, and submitting AI text as your own is another; check the rules of each course.

Wrap-up · What to take with you

From today to next week

The method you used for the study guide applies to any task you repeat. Write it with CREATE, save it once, test it with the checks and improve the file when an answer goes wrong.

What we covered

  • An LLM writes the most likely next token, so the context decides much of the quality.
  • The harness builds that context and runs the tools.
  • An agent is a model that uses tools in a loop and chooses its own next step.
  • A skill is a written procedure that the harness loads when it is needed.

Ideas for your next skill

  • Rewrite a message to a landlord or a professor in Portuguese, in the right level of formality.
  • Turn a reading assignment into questions to discuss in class.
  • Plan a weekend trip with a fixed budget, asking the model to search prices instead of guessing them.

About this session

AI Basics for Exchange Students · 29/10/2026 · Prof. Afonso

Learning objective

By the end of the session, participants should be able to explain what a large language model, a harness, an agent and a skill are and how they relate, write a prompt for a recurring task using the six parts of the CREATE method, save that prompt as a skill in the Agent Skills format and install it as a Google Gemini Gem or as a Claude project, and test the answers against the rules of the skill, including checking that information missing from the source is flagged rather than invented.

Session strategy

One-hour in-person workshop for international exchange students at Inteli, from 10:00 to 11:00, with participants on their own laptops and free accounts. The first twenty minutes explain four concepts with three live animations: token-by-token generation with and without a fictional syllabus in the context, the think, act and observe loop of an agent, and a skill being loaded into the context. The next fifteen minutes present the CREATE method by contrasting a short prompt with a complete one and show how its six parts become the sections of a SKILL.md file. In the fifteen-minute hands-on, each participant installs a study-guide skill as a Gem or as a Claude project, runs it on fictional class notes that contain two deliberate traps, checks the answer against five criteria, changes one line of the skill and tests it on their own notes. The session closes with the limits of the tools, privacy and course policies on AI.
