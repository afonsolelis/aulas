Class notes (sample, fictional) - Software Engineering, class 3
Topic: requisitos funcionais e não funcionais (functional and non-functional requirements)
Notes taken by an exchange student; part of the class was in Portuguese.

- Professor started with a case: an app for booking university study rooms ("reserva de salas").
- Requisito funcional = what the system does.
  Examples from the case: student books a room; student cancels a booking; admin blocks a room for maintenance.
- Requisito não funcional = how well the system does it, a quality ("atributo de qualidade").
  Examples: the booking page must load in less than 2 seconds; the system must work on mobile phones;
  personal data must follow the LGPD (Brazilian data protection law).
- He said a good non-functional requirement must be measurable ("mensurável").
  Bad: "the system must be fast". Good: "95% of bookings confirmed in under 3 seconds".
- "Critério de aceite" = acceptance criterion: the condition that tells if a requirement was met.
- There is an ISO standard that lists quality characteristics. He said the number but I missed it. Check.
- Prioridade: requirements are ranked with MoSCoW (must, should, could, won't).
  The room booking itself is "must"; dark mode is "could".
- Homework ("tarefa"): write 3 functional and 2 non-functional requirements for the room booking app,
  each one with an acceptance criterion. Due next class.
- Next class: "casos de uso" (use cases).
