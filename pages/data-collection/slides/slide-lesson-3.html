Cenário condutor · Problema

Converter preços em libras para reais

Uma livraria importadora precisa saber, todo dia, quanto cada título custaria em reais. O preço está num site em libras; o câmbio, numa API do Banco Central. O monitor da aula busca os dois e guarda tudo no MinIO.

Fonte 1 · scraping

books.toscrape.com: 1.000 livros em 50 categorias, preço em libras. Site de treino. Scraping é ler a página feita para pessoas e tirar dela os dados, porque o site não oferece outra forma de acesso.

Fonte 2 · API

PTAX do Banco Central: cotação GBP para BRL, sem chave. A API devolve os dados prontos para programas, em JSON, num endereço documentado.

Resultado da aula

HTML e JSON brutos em raw, exatamente como a fonte entregou; livros.jsonl e cotacoes.jsonl em bronze, com um registro por linha (JSON Lines), já separados em campos.

API, REST e recurso

API (Application Programming Interface) é a porta que um sistema abre para outro programa pedir dados sem passar pela tela feita para pessoas. REST é o estilo mais comum dessas portas na web: cada coisa que se pode pedir tem um endereço próprio e é lida com os verbos do HTTP.

Etapa 00 · Teoria · Conceito

O bruto e o extraído de uma mesma página

Bruto é a resposta da fonte exatamente como chegou: os bytes do HTML ou do JSON, sem nenhuma interpretação. Extraído é o que o código tira desses bytes, campo a campo, depois de escolher seletores e converter tipos. Extrair é sempre uma interpretação, e toda interpretação pode errar.

Bruto · detalhe do Sharp Objects, 14.847 bytes 
<h1>Sharp Objects</h1>
<p class="price_color">£47.82</p>
<p class="instock availability">
    In stock (20 available)
</p>
<p class="star-rating Four">...</p>
<tr><th>UPC</th><td>e00eb4fd7b871a48</td></tr>
... mais cerca de 300 linhas de HTML

Guarda tudo, inclusive o que hoje ninguém usa. Quem lê precisa interpretar.

Pronto para consulta, mas só tem os campos que o seletor conhecia. Se o seletor errou, o erro está gravado.

Etapa 00 · Teoria · Decisão de arquitetura

Três situações em que o bruto salva o dado

Reprocessar é rodar a extração de novo sobre bytes já guardados, sem chamar a fonte. Só é possível se o bruto existe. A página de uma data passada não volta mais: o site mostra apenas o preço de hoje.

Seletor errado

O preço saiu vazio durante uma semana. Corrige-se o seletor e reprocessa-se a semana a partir do raw.

Sem bruto: a semana está perdida.

Pergunta nova

Alguém quer a avaliação em estrelas, que o extrator ignorava. Extrai-se o campo novo para todo o histórico.

Sem bruto: o histórico começa hoje.

Site mudou

A página nova quebra o seletor. Compara-se o HTML antigo com o novo e acha-se a tag que mudou.

Sem bruto: resta adivinhar.

Falhar de forma visível

A listagem declara 20 livros e o extrator achou zero: a extração para com erro, em vez de gravar um JSON Lines vazio como se fosse resultado válido. É a mesma camada raw da Aula 02, com bytes como chegaram e a procedência anotada.

Etapa 01 · Teoria · O que é web scraping

Ler com um programa uma página feita para pessoas

Web scraping é baixar uma página web e extrair dela, por programa, os dados que uma pessoa leria na tela. O catálogo de livros não tem API: não existe um endereço que devolva os preços em JSON. O único caminho é baixar o HTML de cada página e procurar os valores dentro dele.

O books.toscrape.com é um site de treino, feito para ser raspado: avisa na própria página que preços e avaliações são inventados. Um site real exige as verificações da Etapa 04 antes do primeiro script.

Etapa 01 · Teoria · Escolha da fonte

Os caminhos até o dado e o que os bloqueia

Antes de escrever o coletor, decide-se por onde o dado entra. Os termos abaixo aparecem na tabela do próximo slide.

Caminhos
  • API: endereço feito para programas, com contrato documentado. A PTAX é uma.
  • Exportação oficial: arquivo publicado pelo dono do dado, como CSV ou dump de banco.
  • Dados abertos: portais públicos de exportação oficial, como o dados.gov.br.
  • Scraping: ler o HTML feito para pessoas, como no catálogo de livros.
Bloqueios
  • Login: a página só abre com conta; coletar exige credencial de alguém.
  • Paywall: conteúdo só para assinante.
  • CAPTCHA: teste para separar pessoa de robô; contorná-lo viola a intenção do site.
  • Termos de uso: contrato do site; pode proibir coleta mesmo sem bloqueio técnico.
  • Base legal: na LGPD, o motivo previsto em lei que autoriza tratar dado pessoal, como consentimento ou obrigação legal.

Etapa 01 · Teoria · Pausa para reflexão

Quatro fontes para uma rede de postos

Uma rede de postos compara seus preços com o mercado. Qual caminho para cada fonte, e por quê? A ANP (Agência Nacional do Petróleo, Gás Natural e Biocombustíveis) regula os combustíveis e pesquisa preços nos postos.

Preços da ANP

Etapa 02 · Teoria · Câmbio

A cotação GBP/BRL diz quantos reais custa uma libra esterlina. Cada boletim traz dois preços, porque quem negocia moeda compra mais barato do que vende.

Cotação de compra

Reais que a instituição paga por uma libra que alguém vende a ela. No fechamento de 16/10, cotacaoCompra foi 6,7733.

Cotação de venda

Reais que a instituição cobra por uma libra que alguém compra dela. No mesmo boletim, cotacaoVenda foi 6,7756.

Paridade

Relação da moeda com o dólar. paridadeVenda 1,3331 significa 1,3331 dólar por libra. Fica no bruto; o bronze não usa.

A conta que a Aula 04 vai fazer

A livraria importa: ela compra libras para pagar o fornecedor, então paga a cotação de venda. Sharp Objects custa £47,82; com o fechamento de 16/10, são 47,82 × 6,7756 = R$ 324,01. Com a cotação de compra, a conta daria R$ 323,90. A diferença parece pequena num livro e deixa de ser num catálogo de mil títulos repetido todo dia.

Nesta aula, o monitor só grava a resposta da API e extrai os boletins. A conversão para reais acontece na Aula 04.

Etapa 03 · Teoria · Recursos e resposta

Um dia ou um período, a mesma lista value

Os dois recursos devolvem um objeto JSON com a lista value, um item por boletim. Quando não há boletim, a lista vem vazia, e o status continua 200.

// CotacaoMoedaDia, GBP, 10-16-2026 (último item)
{
  "@odata.context": "...#_CotacaoMoedaDia",
  "value": [
    ...,
    { "paridadeCompra": 1.33280,
      "paridadeVenda": 1.33310,
      "cotacaoCompra": 6.77330,
      "cotacaoVenda": 6.77560,
      "dataHoraCotacao": "2026-10-16 13:04:14.548156",

CotacaoMoedaDia(moeda, dataCotacao)

Todos os boletins de um único dia. O fechamento se chama Fechamento PTAX.

Todos os boletins dos dias úteis do intervalo. O mesmo fechamento se chama Fechamento.

Consequência

Um filtro escrito para um recurso não acha nada no outro. O teste do extrator precisa usar a resposta do recurso que o coletor chama.

Etapa 03 · Teoria · Formato de data

Três formatos de data, três respostas diferentes

A PTAX espera MM-DD-AAAA, o padrão americano: mês, dia e ano. Os outros dois formatos comuns no Brasil e em programação produzem respostas que enganam o coletor.

Formato enviadoExemplo para 15/10Resposta observadaO que significa
MM-DD-AAAA'10-15-2026'200, cinco boletinso formato que a API documenta
ISO AAAA-MM-DD'2026-10-15'200, "value": []erro silencioso: parece sucesso, é igual à resposta de um feriado
DD-MM-AAAA'15-10-2026'500 em 0,23 serro do cliente com código de erro do servidor; repetir não resolve
Erro silencioso

Falha que não gera exceção nem status de erro. O coletor grava uma lista vazia, e ninguém percebe até faltar cotação na Aula 04. A defesa é validar o formato antes de chamar e tratar lista vazia em dia útil como alerta.

Corpo do 500

Vem como /*{"codigo":500,"mensagem":"Erro desconhecido"}*/. JSON não aceita comentários /* */, então json.loads falha. Guardar a resposta bruta mantém a prova do erro.

Etapa 03 · Teoria · Observado em 03/10 e 16/10/2026

O que a documentação da PTAX omite

O contrato de uma API é o que ela promete na documentação: recursos, parâmetros, formatos e campos. O comportamento real só aparece chamando a API com datas sem cotação e formatos errados, e registrando o que volta.

SituaçãoRespostaConsequência para o coletor
sábado200, value: []consultar uma janela de dias e registrar a data da cotação usada
data em ISO200, value: []erro silencioso; validar o formato antes de chamar
data DD-MM-AAAA500 "Erro desconhecido"500 causado pelo cliente; o retry precisa de limite
fechamentoFechamento PTAX (Dia) e Fechamento (Período)o filtro depende do recurso; testar

Nenhuma das quatro situações aparece como erro de rede. Guardar a resposta inteira antes de interpretar permite corrigir o filtro e reprocessar sem chamar a API de novo. A resposta também vem sem ETag, então não há como perguntar se ela mudou.

Etapa 04 · Teoria · Árvore DOM

Elementos dentro de elementos formam uma árvore, o DOM (Document Object Model). O de fora é o pai, os de dentro são filhos, e o coletor desce até a folha que guarda o valor.

Etapa 04 · Teoria · Paginação no monitor

Como as duas fontes paginam

PTAX: offset

Etapa 04 · Teoria · Ética e conformidade

Termos de uso, LGPD, User-Agent e cadência

Termos de uso

Contrato que o usuário aceita ao usar o site. Sites comerciais costumam proibir coleta automatizada, e a proibição vale mesmo sem robots.txt. Este catálogo existe para treino.

LGPD e dado pessoal

A Lei 13.709/2018 protege informação ligada a uma pessoa identificável: nome, foto, e-mail. Publicado, continua pessoal. O catálogo não tem; avaliações com nome do autor teriam.

User-Agent

Cabeçalho em que o cliente diz quem é; o padrão do requests é python-requests/ e a versão. O monitor manda o projeto e um contato, para o dono avisar antes de bloquear.

Cadência, threads e bloqueio

Cadência é o intervalo entre requisições (1 s, hipótese). Dez threads fazem dez pedidos ao mesmo tempo, o que parece ataque; o servidor responde 429 ou 403 ou recusa o IP. Isso é o bloqueio.

Uma página que não respondeu em 20 s

Etapa 05 · Teoria · Mecanismo

Timeout de conexão e timeout de leitura

Uma requisição tem duas fases, e cada uma tem o seu limite. O primeiro número da tupla vale para abrir a conexão; o segundo, para o silêncio entre os bytes da resposta.

O timeout de leitura conta o silêncio entre dois pedaços da resposta, e não a duração total do download. As escalas são ilustrativas, exceto a mediana e o caso de 16/10.

Etapa 05 · Teoria · Conceito

Status code: quem errou, cliente ou servidor

O status code é o número de três dígitos na primeira linha da resposta. O primeiro dígito, a família, já diz o tipo de resultado.

FamíliaSignificaExemplo

Etapa 05 · Teoria · Códigos de status

O status code decide a próxima ação

Para cada resposta, o coletor escolhe entre gravar, repetir ou registrar a falha e seguir. Repetir só ajuda quando o problema é passageiro.

CódigoSignificadoColetor

Retry-After é o cabeçalho em que o servidor diz quantos segundos esperar. Backoff é esperar cada vez mais entre tentativas (Etapa 08). Exceção: a PTAX devolve 500 para data em formato inválido (Etapa 03), e repetir não resolve; por isso o limite de tentativas é obrigatório.

Etapa 05 · Teoria · Falhas de rede

Falha que passa sozinha e falha que não passa

Retry é repetir a mesma requisição depois de uma falha. Ele só faz sentido quando a causa é temporária: a mesma pergunta, feita de novo alguns segundos depois, pode receber outra resposta.

Transitória: vale repetir

O problema está no momento, e não no pedido.

  • timeout ou conexão recusada: rede lenta ou servidor ocupado
  • 408: o servidor cansou de esperar o pedido
  • 429: o cliente passou da cota de requisições
  • 500, 502, 503, 504: servidor, proxy ou gateway com problema
Permanente: repetir não muda nada

O problema está no próprio pedido.

  • 400: pedido malformado
  • 401 e 403: sem credencial ou sem permissão
  • 404: o recurso não existe nessa URL
  • PTAX com data em DD-MM-AAAA: devolve 500 toda vez (Etapa 03)

O último exemplo mostra o limite da regra: um código da família 5xx causado pelo cliente. Por isso, além de escolher o que repetir, o coletor precisa de um número máximo de tentativas.

Etapa 05 · Teoria · Autenticação

Chave de API: no cabeçalho, nunca na URL

Chave de API é uma senha de programa: identifica quem chama, para a fonte cobrar, limitar ou bloquear. A PTAX e o catálogo não pedem chave; muitas APIs comerciais pedem.

Na URL: vaza

A URL fica gravada no log do servidor, no proxy, no histórico do terminal e no manifesto da coleta. Quem lê qualquer um deles copia a chave.

GET /precos?api_key=abc123   # exemplo fictício
No cabeçalho: fica fora dos registros

A chave vai num cabeçalho e é lida do .env, que não entra no Git. O manifesto registra a URL sem a chave.

GET /precos
Authorization: Bearer ${API_KEY}   # do .env

Etapa 06 · Teoria · Formato do bronze

JSON Lines: um registro por linha

JSON Lines (extensão .jsonl) é um arquivo de texto em que cada linha é um objeto JSON completo, terminado por quebra de linha. Não há colchetes envolvendo o arquivo nem vírgula entre registros.

Uma linha do livros.jsonl · 274 bytes contando a quebra de linha 
{"upc": "e00eb4fd7b871a48", "url": "https://books.toscrape.com/catalogue/sharp-objects_997/index.html", "titulo": "Sharp Objects", "categoria": "Mystery", "avaliacao": 4, "preco_gbp": 47.82, "em_estoque": true, "qtd_estoque": 20, "coletado_em": "2026-10-16T12:31:07+00:00"}

O horário de coletado_em é ilustrativo; os nove campos e os 274 bytes são os do exemplo do material.

Contar

wc -l conta registros. 1.000 linhas no dia significam 1.000 livros.

Ler aos poucos

O leitor processa linha a linha, sem carregar o arquivo inteiro na memória.

Falhar pouco

Uma linha corrompida afeta um registro; num JSON único, quebra o arquivo todo.

Etapa 06 · Teoria · Desenho das chaves

Anatomia de uma chave no MinIO

A chave é o nome completo do objeto dentro do bucket. Como visto na Aula 02, não há pastas: as barras só separam trechos, e cada trecho inicial forma um prefixo que se pode listar.

Partição no formato nome=valor

Partição é o trecho da chave que agrupa os objetos de um mesmo dia. Listar o prefixo raw/books_toscrape/data=2026-10-24/ traz só aquele dia, sem varrer o ano inteiro. A forma nome=valor é lida como coluna pelo DuckDB na Aula 04.

Data de referência

A data da partição é a da coleta em America/Sao_Paulo. Em UTC, uma execução depois das 21h de Brasília cairia no dia seguinte.

Etapa 06 · Teoria · Desenho das chaves

Chave determinística contra chave com horário

Determinística é a chave calculada só a partir da fonte, da data e da página: a mesma página no mesmo dia gera sempre a mesma chave. Gravar de novo sobrescreve o objeto em vez de criar outro.

Determinística

.../data=2026-10-24/categoria=mystery_3/pagina=001.html

Retry ou reexecução no mesmo dia caem na mesma chave: um objeto por página.

Com horário

.../pagina=001_20261024T091503.html

Cada tentativa ganha nome novo: o bucket acumula cópias da mesma página.

raw/books_toscrape/data=2026-10-24/categoria=mystery_3/pagina=001.html
raw/books_toscrape/data=2026-10-24/livro=sharp-objects_997/detalhe.html
raw/ptax/moeda=GBP/data=2026-10-24/cotacao_moeda_periodo.json
raw/manifestos/data=2026-10-24/execucao=20261024T093012-0300.json   exceção: uma por execução
bronze/books_toscrape/data=2026-10-24/livros.jsonl
bronze/ptax/moeda=GBP/data=2026-10-24/cotacoes.jsonl

O custo: perde-se a versão intermediária de uma página que mudou entre duas execuções do mesmo dia. Para um monitor diário, esse é o grão desejado.

Etapa 06 · Teoria · Procedência

Metadados são pares nome e valor gravados junto ao objeto, fora dos bytes. Os definidos pelo usuário recebem o prefixo x-amz-meta-, herdado da API S3 da Amazon que o MinIO imita. Eles dizem de onde o objeto veio sem abri-lo.

  • ASCII: os 128 caracteres básicos, sem acento nem £. Metadado só aceita ASCII: com preço, o boto3 recusa com ParamValidationError; use preco.
Etapa 06 · Teoria · Procedência

SHA-256: a impressão digital dos bytes

Hash é uma função que transforma qualquer sequência de bytes num código de tamanho fixo. O SHA-256 gera 64 caracteres hexadecimais. Os mesmos bytes dão sempre o mesmo código; mudar um único byte muda o código inteiro, e não há como voltar do código para os bytes.

Um byte de diferença

47.82

c0caab077271d6f092416c0fe06b4de059e4ce38ed732e9d20ccae70f5015343

47.83

f48103ace8ff76ba982d2c6dca16302328cfcc1e96a238b91e6dd4bb8daac43c

A página inteira do Sharp Objects, 14.847 bytes baixados em 23/10/2026, tem o SHA-256 41ae9ef1bc17c9984b8e452c61f3370fc6e1868e9b699c803c7336136f57c0ef.

Integridade

O hash do que foi baixado, comparado ao do objeto no MinIO, prova que nada se corrompeu no caminho.

Mudança

Hash igual ao de ontem: a página não mudou. Hash diferente: algo mudou, mesmo que seja um espaço.

Rastro

O manifesto e os metadados guardam o mesmo hash, ligando o registro ao objeto.

Etapa 08 · Teoria · Conceito

Seguro e idempotente: o que pode ser repetido

Depois de um timeout, o coletor não sabe se o servidor chegou a executar o pedido. Repetir só é inofensivo quando o pedido tem uma destas duas propriedades, definidas na RFC 9110, a norma do HTTP.

Seguro

O pedido só lê; o servidor não muda nada. Pedir a página inicial do catálogo cem vezes não altera o catálogo.

Idempotente

Repetir o pedido deixa o servidor no mesmo estado que fazer uma vez só. O resultado final não depende de quantas vezes chegou.

POST de um pagamento

Exemplo: o pedido chega, o servidor cobra, a resposta se perde. O cliente repete e o cartão é cobrado duas vezes. Não é seguro nem idempotente.

GET de uma página

O timeout se repete e o coletor pede de novo. O servidor só entrega a mesma página. Seguro e idempotente.

PUT no MinIO

Gravar a mesma chave com os mesmos bytes duas vezes deixa um objeto só. Muda o servidor, mas é idempotente.

Etapa 08 · Teoria · Backoff

Esperar antes de repetir, e cada vez mais

Um servidor sobrecarregado responde 503 a cem coletores. Se os cem repetirem na hora, a carga volta inteira e o servidor cai de novo: é o efeito manada. Backoff é a espera entre uma tentativa e a seguinte.

Backoff exponencial

A espera dobra a cada tentativa: base × 2k, com k começando em 0. Com base de 1 s:

Tentativa que falhoukEsperaVolta em
1ª01 s1 s
2ª12 s3 s
3ª24 s7 s
4ª38 s15 s
Teto

Sem limite, a décima espera seria de 512 s. O teto corta a conta: a espera nunca passa dele, por exemplo 30 s no cliente HTTP da Etapa 12.

O que ainda falta

Se os cem coletores usam a mesma conta, todos esperam 1 s e voltam juntos em 1 s; depois juntos em 3, 7 e 15 s. O backoff espaça as tentativas de cada coletor, mas não separa um coletor do outro.

Etapa 08 · Teoria · Backoff e jitter

Três jeitos de voltar depois de um 503

Cada ponto é um coletor chegando ao servidor. Jitter é sortear a espera: cada coletor tira um número diferente, e as chegadas deixam de coincidir.

Posições da terceira linha ilustrativas. O exemplo numérico 1 mede o efeito com cem coletores.

Etapa 08 · Teoria · Full jitter

A fórmula da espera, parte por parte

Lida em voz alta: a espera é um número sorteado entre zero e o menor valor entre o teto e a base vezes dois elevado ao número da tentativa. Full jitter quer dizer que o sorteio cobre a faixa inteira, desde zero.

espera = aleatorio(0, min(teto, base * 2 ** tentativa))
PedaçoO que fazCom base 1 s, teto 30 s, tentativa 2
base * 2 ** tentativabackoff exponencial: dobra a cada tentativa1 × 22 = 4 s
min(teto, ...)corta a espera no tetomin(30, 4) = 4 s
aleatorio(0, ...)sorteia um valor entre 0 e o limite: é o jitterqualquer valor de 0 a 4 s, por exemplo 2,7 s

O coletor também precisa de um prazo para cada tentativa: requests.get(url, timeout=(5, 20)) espera até 5 s para conectar e até 20 s pela resposta. Sem esse prazo, a tentativa não termina e o retry nunca começa.

Etapa 08 · Teoria · Rate limit

Quando o servidor diz quanto esperar

Rate limit é a cota de requisições que um servidor aceita de cada cliente por intervalo de tempo, por exemplo 60 por minuto. Quem passa da cota recebe 429 Too Many Requests.

Cabeçalho Retry-After

Junto com o 429 ou o 503, o servidor pode mandar Retry-After: 2, que significa: volte daqui a 2 segundos. O valor do servidor substitui o sorteio, porque ele conhece a própria cota e o coletor não.

Limite de tentativas

O coletor desiste depois de HTTP_MAX_TENTATIVAS (4 no .env.example da aula) e grava a falha no manifesto, com URL, status e número de tentativas. Assim a falha permanente que parecia transitória, como o 500 da PTAX, não vira laço infinito.

Etapa 08 · Teoria · Retry

As três regras do retry no coletor

O que os slides anteriores decidem, numa lista que vira requisito na construção.

  1. Repetir só o transitório: timeout, erro de conexão, 408, 429 e 5xx. O resto vai direto para o manifesto.
  2. Esperar com backoff exponencial e full jitter; com Retry-After, esperar o que o servidor pediu. Parar no limite de tentativas.
  3. Repetir só operação idempotente, aquela que produz o mesmo efeito se feita duas vezes: GET na fonte; no MinIO, mesma chave e mesmos bytes.

          Etapa 09 · Conceitos
          
O que é uma ADR

          
Architecture Decision Record, proposta por Michael Nygard em 2011: um arquivo curto por decisão de arquitetura, guardado no repositório. Quem chega depois lê por que o sistema é assim.

        

        
Contexto
O problema e o requisito que forçam a decisão. Exemplo: RNF-04 e os cem clientes que voltam juntos depois de um 503.
Decisão
O que foi escolhido, em uma ou duas frases.
Alternativas
As opções descartadas e por quê. Sem elas, a ADR vira anúncio da escolha.
Consequências
O que melhora e o que custa. Full jitter reduz o pico e faz a duração da coleta variar.
Status
Proposta quando escrita, Aceita quando o grupo aprova, Substituída quando outra ADR a troca. A ADR aceita não é reescrita.
Tática de qualidade
Decisão de projeto que melhora um atributo de qualidade, como retry para confiabilidade. Cada tática da manhã vira uma ADR.

          Etapa 11 · Conceitos
          
Teste primeiro: vermelho, depois verde

          
No desenvolvimento guiado por testes (TDD), o teste é escrito antes do código. Ele falha porque a função ainda não existe, e só então o código é escrito para fazê-lo passar.

        

        
Vermelho
O teste roda e falha pelo motivo certo: ImportError ou NotImplementedError, nunca erro de digitação no próprio teste.
Verde
O código mínimo que faz o teste passar. Depois, com tudo verde, o código pode ser arrumado sem medo.
pytest
Ferramenta que acha as funções test_* em tests/, roda cada uma e mostra quantas passaram. pytest -q resume a saída.
Teste unitário
Testa uma função isolada, sem rede e sem MinIO. Roda em milissegundos e dá o mesmo resultado sempre.
Teste de integração
Testa a conversa com um serviço real, aqui o MinIO local no bucket teste. Fica marcado com @pytest.mark.minio.
Por que antes
O teste escrito depois tende a confirmar o que o código já faz. Escrito antes, ele confere o critério de aceite.

          Etapa 11 · Teoria · Codificação de caracteres
          
Bytes, charset e o símbolo da libra

          
A rede só transporta bytes, números de 0 a 255. Charset (ou codificação) é a tabela que diz qual caractere cada byte representa. No UTF-8, a libra ocupa dois bytes, C2 A3; no ISO-8859-1, cada byte é sempre um caractere. Os mesmos dois bytes dão resultados diferentes conforme a tabela usada.

          Etapa 17 · Conceitos
          
ATAM: procurar riscos na arquitetura

          
Architecture Tradeoff Analysis Method, do SEI da Carnegie Mellon, visto na Aula 01. Parte dos direcionadores de negócio e testa a arquitetura contra cenários concretos.

        

        
Utility tree
Árvore que vai do atributo de qualidade (confiabilidade) ao refinamento (falha de rede) e ao cenário. Cada folha recebe prioridade de importância e de dificuldade.
Cenário de qualidade
Seis partes: fonte do estímulo, estímulo, artefato, ambiente, resposta e medida. Exemplo: o proxy do Railway devolve 502 ao gravador, e a medida é zero objeto duplicado.
Risco e não risco
Risco é decisão que pode falhar um cenário importante. Não risco é decisão que, conferida, atende.
Ponto de sensibilidade e trade-off
Sensibilidade: um parâmetro muda muito uma qualidade, como o intervalo da coleta. Trade-off: melhora uma e piora outra, como cadência educada contra tempo de coleta.
Cobertura
Percentual das linhas de src/ que os testes executaram, medido com pytest --cov=src. Anota-se o número medido.
CI
Integração contínua: o GitHub Actions roda os testes a cada push. Um service container sobe o MinIO ao lado do job para os testes de integração.

  1. Toda requisição tem timeout de conexão e de leitura; sem ele, a falha fica invisível.

    3.

    5.
