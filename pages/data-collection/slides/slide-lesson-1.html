Spec-Driven Development

Especificar antes de pedir código ao agente

Pedido vago, o agente preenche as lacunas sozinho: imagem, porta, onde guardar a senha, console público ou não.

Com SDD

Persona, objetivos, requisitos e plano ficam em arquivos. Cada prompt lê esses arquivos, e cada artefato é revisado e versionado antes da etapa seguinte.

SDD · Ciclo

Sete etapas, um prompt CREATE por etapa

Personadocs/00
Objetivosdocs/01
Specspecs/spec.md
Planospecs/plan.md
Tarefasspecs/tasks.md
Implementaçãouma tarefa por vez
ATAMdocs/atam.md

Depois de cada prompt: "Revise antes de seguir", registro em docs/prompts.md e commit.

Revisão humana

O que a IA costuma errar

  1. Inventa números: "99,9%", "200 ms" sem origem
  2. Escolhe tecnologia por moda: Kubernetes, Terraform, proxy
  3. Concorda consigo mesma ao avaliar o próprio plano
  4. Transforma hipótese em fato entre uma etapa e outra
  5. Declara sucesso sem mostrar a saída do comando

Prompts para agentes

Sete práticas para trabalhar com o agente

  1. Um prompt por etapa
  2. Contexto por arquivo, não por memória da conversa
  3. Plano antes de editar, com confirmação
  4. Critério de parada explícito
  5. Gates verificáveis por comando
  6. Revisão do diff antes do commit
  7. Segredos fora do prompt e fora do que o agente lê

Conferência · T-01

MinIO local com docker compose

sed -i "s|^MINIO_ROOT_PASSWORD=.*|MINIO_ROOT_PASSWORD=$(openssl rand -hex 24)|" .env
docker compose config --quiet && echo "compose ok"
docker compose up -d --wait
docker compose ps                     # healthy
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:9000/minio/health/live   # 200

docker compose down preserva o volume; down -v apaga.

Conferência · T-06

Deploy no Railway pelo terminal

cd aula_01_minio/minio_railway
railway init --name minio-grupo-xx
railway add --service minio
railway service link minio
railway volume add --mount-path /data
# GRUPO, outro terminal: usuário e senha (--stdin) no Railway e no .env
railway up --detach
railway domain --port 9000 --service minio
Conferência · T-04 e T-07

Buckets, acesso negado e persistência

set -a; . ./.env; set +a
mc alias set railway "$MINIO_RAILWAY_ENDPOINT" "$MINIO_RAILWAY_USER" "$MINIO_RAILWAY_PASSWORD"
for b in raw bronze silver gold; do mc mb --ignore-existing "railway/$b"; done
curl -s -o /dev/null -w "%{http_code}\n" "$MINIO_RAILWAY_ENDPOINT/raw"   # 403
mc cp /tmp/teste.json railway/raw/_verificacao/teste.json
railway redeploy --service minio --yes
mc ls railway/raw/_verificacao/       # o objeto continua lá

Objetivo de aprendizagem

Ao final do encontro, o estudante deve ser capaz de descrever a arquitetura de software de um projeto de dados em Spec-Driven Development, da persona e dos objetivos de negócio à especificação, ao plano, às tarefas e à validação ATAM, e publicar um MinIO próprio no Railway pelo terminal.

Estratégia do encontro

Demonstração prática completa: a teoria ocupa a primeira parte do encontro e, em seguida, o professor constrói o projeto ao vivo enquanto cada aluno reproduz o mesmo caminho no próprio repositório, com o agente de código guiado pelo AGENTS.md e prompts no formato CREATE.
