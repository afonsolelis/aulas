2. Objetivo de aprendizagem

Ao final do encontro, o estudante deve ser capaz de instalar e verificar o .NET SDK 9 no próprio sistema operacional, distinguir SDK de runtime, criar e versionar no repositório do grupo um projeto Blazor Web App com renderização no servidor e conduzir o discovery inicial dos dados do projeto, em arquivos e no banco, registrando fontes, tabelas, campos e hipóteses.

Resultados observáveis

  • Executar o checklist anterior à instalação e verificar SDKs e runtimes já presentes com dotnet --list-sdks e dotnet --list-runtimes.
  • Explicar por que o desenvolvimento exige o SDK enquanto a execução de uma aplicação compilada exige apenas o runtime, e descrever o percurso do C# até o código nativo pela IL, pelo CLR e pelo JIT.
  • Instalar o SDK pelo caminho indicado para Windows, macOS ou Linux e diagnosticar falhas de PATH e de versão com where dotnet e dotnet --info.
  • Criar o projeto com dotnet new blazor, executá-lo com dotnet watch e descrever o fluxo de SSR, do HTML inicial entregue pelo servidor à ativação da interatividade.
  • Identificar as responsabilidades dos projetos de uma solution .NET (WebApi, Web, Services, Repository e Tests) e a cadeia de dependências entre eles.
  • Diferenciar máquina virtual de container e verificar a instalação do Docker e do Docker Compose.
  • Usar o agente do Antigravity para analisar arquivos de dados e consultar o information_schema do banco para listar tabelas e colunas candidatas ao domínio.

3. Produtos do encontro

Ambiente

SDK 9 instalado e verificado em cada máquina, Docker operante e smoke test concluído com um console app executado por dotnet run.

Projeto

Projeto NomeDoGrupo.Dashboard criado na raiz do repositório do grupo, executando localmente e com o commit da estrutura inicial enviado.

Inventário de dados

Primeiro levantamento das fontes, tabelas e campos, com chaves, cardinalidades, lacunas de qualidade e hipóteses sobre os campos críticos para os indicadores do dashboard.

Os três produtos correspondem ao entregável da Aula 1 descrito no material: ambiente funcional com o projeto Blazor rodando localmente, checklist pós-instalação validado em grupo e primeiro inventário de dados.

4. Preparação

Responsabilidade dos grupos

  • Trazer o computador com o sistema atualizado e ao menos 2 GB livres em disco.
  • Confirmar que há um terminal funcional (PowerShell, Terminal, bash ou zsh).
  • Garantir acesso ao repositório do grupo no GitLab.
  • Ter uma conta Google para o login no Antigravity.
  • Reunir em uma pasta local os arquivos de dados do projeto.
  • Estar conectado à rede do Inteli para acessar o PostgreSQL.

Responsabilidade do docente

  • Conferir a disponibilidade do servidor PostgreSQL do Inteli e os parâmetros de conexão projetados no slide.
  • Manter abertos os endereços oficiais de download do .NET 9, do Docker e do Antigravity.
  • Preparar o repositório aula_dotnet_cars para mostrar a anatomia da solution.
  • Prever a circulação pela sala durante a instalação para verificar erros de PATH e de permissão.
  • Lembrar à turma que, no terceiro ano, a daily ocorre fora do horário de instrução.

Pré-requisitos pedagógicos

  • Uso básico de terminal e de git (clone, add, commit e push).
  • Noções de C#; quem estiver inseguro com a sintaxe recebe no slide de objetivos a referência de comandos básicos da linguagem.
  • SQL elementar, suficiente para executar consultas de leitura sobre o information_schema.

6. Roteiro de condução

Abertura e fundamentos

  1. Apresentar o foco da aula e situá-la como base técnica do restante do módulo, uma vez que a padronização do ambiente reduz o retrabalho do time.
  2. Ler os objetivos e confirmar que a turma distingue SDK de runtime, retomando a síntese do slide segundo a qual sem SDK não se compila e sem runtime não se executa.
  3. Desenhar o caminho do C# até o código nativo (IL, CLR e JIT) e relacioná-lo a desempenho e portabilidade.

Instalação por sistema operacional

  1. Pedir que cada estudante siga o slide do próprio sistema: winget no Windows, Homebrew ou instalador .pkg no macOS, APT no Ubuntu e no Debian, DNF no Fedora.
  2. Lembrar que o terminal deve ser reaberto após a instalação e que, em Macs com Apple Silicon, o terminal não deve rodar sob Rosetta.
  3. Usar where dotnet e dotnet --info para diagnosticar versão errada e recomendar a remoção das versões antigas quando houver conflito.

Projeto do grupo

  1. Rodar o template, comparar Blazor Server, Blazor WebAssembly e Blazor Web App e justificar a adoção do Web App com SSR.
  2. Percorrer o diagrama de SSR em cinco passos, distinguindo o HTML inicial entregue pelo servidor da ativação posterior da interatividade.
  3. Guiar o clone, a criação de NomeDoGrupo.Dashboard e o commit, conferindo que o projeto ficou na raiz do repositório.
  4. Mostrar a solution do repositório aula_dotnet_cars e a separação de responsabilidades entre WebApi, Web, Services, Repository e Tests.
  5. Explicar imagem, container e Docker Compose como meio de manter o ambiente idêntico para todo o time; no Linux, a instalação usa o Docker Engine.

Discovery de dados

  1. Apresentar o Antigravity como apoio para acelerar o entendimento dos dados, cuja conclusão continua cabendo ao grupo.
  2. Executar o prompt de exemplo sobre os arquivos CSV e pedir que cada grupo o adapte ao próprio dataset.
  3. Conectar ao PostgreSQL do Inteli com os parâmetros do slide e indicar, a quem precisar trabalhar fora da rede do Inteli, o caminho do dump com servidor PostgreSQL local.
  4. Executar as consultas ao information_schema e discutir quais tabelas pertencem ao domínio do dashboard.

7. Metodologia

O encontro combina exposição dialogada curta com prática guiada no computador de cada estudante. A instalação ocorre junto com a explicação, de modo que as falhas aparecem em sala e são diagnosticadas com os próprios comandos apresentados. O discovery trabalha sobre os dados do projeto do grupo, e por isso o inventário produzido serve de insumo direto para a modelagem das aulas seguintes.

Prática por sistema operacional

Cada estudante segue o roteiro do seu sistema, e o docente intervém nos erros de ambiente à medida que surgem.

Versionamento desde o início

O projeto nasce no repositório do grupo, o que garante a todos os integrantes a mesma estrutura de partida.

Discovery assistido por IA

O agente produz a primeira leitura dos dados, que o grupo confere com consultas diretas ao banco.

11. Fechamento

O fechamento retoma os três itens do slide de mão na massa, e cada grupo responde às perguntas abaixo.

  1. O SDK 9 e o Docker estão verificados em todas as máquinas do grupo?
  2. O projeto está no repositório, na raiz, e executa localmente?
  3. Que tabelas e campos devem sustentar os primeiros indicadores e que lacunas de qualidade foram encontradas?

Antes de encerrar, o grupo registra no repositório o inventário inicial de dados e as pendências de setup que ficaram abertas.
