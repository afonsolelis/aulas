Module 5 · Software Engineering · Lesson 2

Lesson plan · Data Structures: Fundamentals and Implementations

Dialogued exposition on stacks and queues as ordering strategies, with LIFO and FIFO compared through their operations, their everyday uses and their role in event-driven systems, followed by a one-hour in-class graded activity in which students design the movement logic of a maze robot that backtracks with a stack and uses keys from a queue.

2. Learning objective

By the end of the meeting, students should be able to apply the concepts of Data Structures: Fundamentals and Implementations to the project, within the scope of the fundamentals of the data structures that are essential for building efficient distributed systems.

Observable outcomes

  • Describe the LIFO rule of the stack and the FIFO rule of the queue and execute push, pop and peek, and enqueue, dequeue and front, in Python.
  • Explain that the choice between a stack and a queue is the choice of an ordering strategy, since the same elements produce different behaviour in each structure.
  • Associate stacks with undo history, call stacks, browser navigation and backtracking, and queues with request scheduling, job workers, tickets and event consumption.
  • Relate the FIFO idea to queue-based tools such as RabbitMQ, Kafka, AWS SQS and Celery and to the decoupling and load absorption of event-driven systems.
  • Use a stack to backtrack from dead ends and a queue to consume resources in the order of collection when solving the maze robot problem.

6. Facilitation script

  1. Open with slide 2 and ask the class where the order of processing changes the result of a program it already wrote.
  2. Run the stack example of slide 3 and ask which element pop returns and what remains on top, then do the same with the queue of slide 4.
  3. Use the comparison of slide 5 to state that the difference between the two structures lies in the ordering strategy, since both store the same elements.
  4. On slides 6 and 7, ask the class to add one example of each structure from the project or from tools it uses daily.
  5. Present slides 8 and 9 as the bridge to the module: a producer emits an event, a queue or topic stores it and consumers process it, which decouples components and absorbs load peaks.
  6. On slide 10, ask which structure each scenario needs: returning to a previous step, or processing pending work in arrival order.
  7. Read the context, the rules and the game flow of slide 12 with the class, drawing the maze example on the board, and start the hour of the activity.
  8. During the activity, check first whether the student records every movement on the stack and whether the oldest key is the one used at each door.
  9. Collect the activity at the end of the hour and close with the questions slide.

7. Methodology

The meeting follows the strategy recorded for this encounter, a dialogued exposition alternated with guided application and closed with a check of understanding. The exposition presents each structure through its rule, its operations, a short Python example and a list of real uses, so that the class associates LIFO and FIFO with behaviours it recognises before applying them to a new problem.

The maze robot activity requires both structures in the same algorithm, which forces the student to decide, at each step, whether the situation calls for returning along the most recent path or for consuming the oldest resource. Because the code must print every movement and every key or door event, the trace makes the student reasoning visible to the instructor.

8. Assessment of learning

Graded activity in class

The main evidence is the solution of the maze robot activity, produced within the hour of class. According to the material, the student is expected to implement and use stacks and queues to solve a computational problem, use stacks for backtracking and queues for sequential processing, apply flow control to navigate the maze efficiently and write structured code that manages states and decisions at runtime.

Student blocked on the maze rules

The instructor walks the game flow example of slide 12 step by step on the board with the student, without solving the movement logic.

Divergence between deck and material on the format

The instructor announces one format at the start of the activity, pen and paper or Colab, and keeps it for the whole class.

11. Closing

The meeting closes with the collection of the activity and the questions slide. The proposition carried to the next lessons is that choosing a data structure also chooses a strategy for control flow, and that the queue presented here as FIFO reappears in infrastructure as the mechanism that coordinates distributed work.
