Steps 3 and 4: grain and completeness

The grain is tested before the distributions, because duplicated rows inflate every count that follows. Missing values are then measured column by column and broken down by the dimension that may explain them.

Step 3 · Structure and grain

If the declared key repeats, either the grain is different from what the group assumed or the extract contains duplicates. The repeated rows are inspected side by side before deciding which case applies.

key = ["store_id", "product_id", "date"]
stock.duplicated(subset=key).sum()
(stock[stock.duplicated(subset=key, keep=False)]
      .sort_values(key).head(20))
Step 4 · Completeness

A null rate concentrated in one store or one period points to a failure of the process that produced the data, which is reported to the partner and not imputed silently.

stock.isna().mean().sort_values(ascending=False)
(stock.groupby("store_id")["on_hand"]
      .apply(lambda s: s.isna().mean())
      .sort_values(ascending=False))

Reference for the focused exposition

Step 5: the profile of each column

The univariate profile describes each column on its own. Numeric columns receive summary statistics and an outlier rule, and categorical columns receive their cardinality and most frequent values.

pandas · summary, cardinality and IQR outliers
display(sales["quantity"].describe())
display(sales.nunique().sort_values())

q1, q3 = sales["quantity"].quantile([0.25, 0.75])
iqr = q3 - q1
low, high = q1 - 1.5 * iqr, q3 + 1.5 * iqr
outliers = sales[(sales.quantity < low) | (sales.quantity > high)]
display(len(outliers) / len(sales))

sales["quantity"].plot.hist(bins=50)
Treatment of outliers

The interquartile rule marks values beyond 1.5 times the IQR. A sale of 400 units may be a typing error or a wholesale order, and only the partner can say which.

Cardinality

A column with one value carries no information, and a code column with as many values as rows is an identifier, which changes how it is modelled.

Step 6: relationships between variables

Relationships are examined in three forms: over time, between categories and between numeric measures. Each form answers a different part of the analytical question, and each chart is kept only if it supports a sentence in the log.

Over time

Daily totals reveal seasonality, gaps in the extract and changes of level that a single average hides.

daily = (sales
  .groupby(sales.sold_at.dt.date)
  ["quantity"].sum())
daily.plot()
Between categories

The share of stock-out days in each store is a first draft of the KPI. The full KPI of Lesson 1 also keeps only continuous-use products and groups by week and product.

key = ["store_id", "product_id",
       "date"]
obs = (stock
  .dropna(subset=["on_hand"])
  .drop_duplicates(key,
                   keep="last"))
(obs["on_hand"].le(0)
   .groupby(obs["store_id"])
   .mean())
Between measures

Spearman correlation tolerates skew and outliers. The measures are selected by name, so identifiers stay out of the matrix.

daily_sp = (sales
  .assign(date=sales.sold_at
          .dt.normalize())
  .groupby(key, as_index=False)
  ["quantity"].sum()
  .merge(obs, on=key))
(daily_sp[["quantity", "on_hand"]]
   .corr(method="spearman"))

Step 7: consistency across tables

The relationships declared in the information viewpoint are tested with joins, and the invariants are tested with filters. A join that loses rows changes every indicator built on it, so its volume is measured before the join is used.

Orphan rows

The indicator argument marks rows that found no match. Their share decides whether the join can be used as it is or needs a treatment in the Silver layer.

m = sales.merge(products, on="product_id",
                how="left", indicator=True)
display((m["_merge"] == "left_only").mean())
Invariants from Lesson 1

Each invariant of the canvas becomes one line of code that counts violations. The log records the number of violations, because the decision depends on their volume.

display((stock["on_hand"] < 0).sum())
display((sales["quantity"] <= 0).sum())
display((sales["sold_at"] > pd.Timestamp.now()).sum())

The initial bucket structure of the Data Lake

The Data Lake stores the partner data in an object store, such as MinIO running in Docker or a cloud bucket. A naming convention decided now keeps every later layer findable. Lesson 3 organises these zones into the Bronze, Silver and Gold layers and revisits whether the raw zone keeps an exact or a typed copy.

Bucket and path convention
<project>-landing/                 files exactly as received
  pos/sale_line/2026-10-19/sale_line.csv

<project>-raw/                     sample in Parquet
  <source>/<entity>/ingestion_date=YYYY-MM-DD/
  pos/sale_line/ingestion_date=2026-10-19/part-0.parquet
  erp/stock_position/ingestion_date=2026-10-19/part-0.parquet

<project>-sandbox/                 notebooks and samples
Source and entity

The path names the system of origin and the information object, so the lineage of a file can be read from its location.

Ingestion date

The key=value form is understood as a partition by pandas, Spark and query engines, which read only the dates a query needs.

Reference for the group practice

Storing the sample as Parquet

Parquet is a columnar format that stores the schema with the data. The write replaces the partition of the day, so a rerun does not duplicate rows. Reading the file back and comparing its types with the inventory of step 2 verifies the conversion.

pandas + pyarrow · write and read back
sales["ingestion_date"] = "2026-10-19"
# local stand-in for the <project>-raw bucket
sales.to_parquet("lake/raw/pos/sale_line",
    engine="pyarrow",
    partition_cols=["ingestion_date"],
    index=False,
    existing_data_behavior="delete_matching",
    basename_template="part-{i}.parquet")

back = pd.read_parquet("lake/raw/pos/sale_line")
display(back.dtypes)     # compare with step 2
len(back) == len(sales)
Columnar

A query that needs two columns reads two columns, which reduces input and output on wide tables.

Typed schema

Dates and numbers keep their types, unlike CSV, where every value is text.

Compression

Values of the same column compress well together, which reduces storage cost.

Predicate pushdown

Column statistics let readers skip blocks that cannot match a filter.
