0:05 · Chart selection
The job of the data chooses the chart

A chart is chosen by the question it must answer, not by the variety of the library. Each question of the DataApp has one job, and each job has a form that the eye reads with the least effort.

Job of the dataQuestion in the DataAppFormAvoid
compare magnitudeswhich sets hold the most expensive cards?horizontal bars ranked, from zeropie with seven slices; bars that start above zero
change over timehow did the value of a set evolve between captures?line, one series highlightedseven coloured lines with a legend
part of a wholewhat share of the market is one set?one sentence or a single stacked bardonut with labels outside it
hierarchyinside a set, which rarity, and inside it which card?bars with drill-down and roll-upa treemap read by colour
one headline numberhow many prices does the fact hold?a number with its label, no charta gauge
how the system workswhat runs, in which order, from where to where?a graph of tasks and a graph of lineagea diagram drawn by hand that drifts from the code
0:10 · Principles
What the eye reads first, and what the chart must not do

Position on a common scale is read more precisely than length, length more than angle and area, and all of them more than colour. A chart therefore places the message in position or length and uses colour only to point at it.

Highlight and context

One accent colour

The series that carries the message is drawn in the accent; every other series stays grey, as context. Seven sets do not need seven colours, which no reader with colour blindness separates.

Direct labels

Text where the eye already is

The value at the end of the bar and the name at the end of the line replace the legend, which forces the eye to travel and back. The grid and the axes stay pale.

The sentence first

Storytelling

Each view opens with the sentence that states the conclusion, with the number that matters, and the chart supports that sentence. A chart without a sentence leaves the conclusion to chance.

Never in this DataAppTwo y axes on the same chart, a bar axis that does not start at zero, a rainbow palette, 3D and a period cut to make a trend look stronger. Each of them changes the conclusion that a reader draws from the same data.

Step 01 · Theory
The infographic is drawn from metadata, not by hand

A diagram drawn by hand describes the system on the day it was drawn. A diagram generated from the catalogue and the run log describes the system that ran, and changes when the code changes.

The catalogue

duckdb_views()

The SQL of every view is in the catalogue. Searching it for the names of the other objects gives the edges of the lineage: gold.fact_price reads db_ingestion, gold.dim_set and gold.dim_product.

The comment

A table forgets its query

A table made by CREATE TABLE AS keeps only its columns. freeze_month writes its source in the comment, and the lineage reads it from duckdb_tables().

The run log

ops.pipeline_tasks

The runner records the graph of each run next to ops.pipeline_runs, so the app draws the DAG without importing the pipeline, which would break the direction of the layers.

Safe by constructionThe dimensions and the measures of the explorer come from fixed lists, and the values chosen by the user are parameters of the query. A set called x' OR '1'='1 returns no rows, and a test proves it.

Step 03 · Theory
A click that changes the state of the app

The selection of a bar arrives after the checkboxes were drawn, and a widget cannot change once it exists in the run. The click is therefore stored as a pending change, the script runs again, and the change is applied at the top, before the widgets.

views/app.py · the drill-down
if "pending" in state:                 # applied before the widgets
    state.path, dims_next = state.pop("pending")
    for d in DIMENSIONS:
        state[f"dim_{d}"] = d in dims_next
...
event = st.altair_chart(chart, on_select="rerun",
                        key=f"bars_..._{len(state.path)}")
picked = event.selection.get("pick")
if picked:                             # one level down
    state.pending = (state.path + [("set_name", ...)], ["rarity"])
    st.rerun()
The key of the chart

The depth of the path is part of the key, so the chart of the new level starts without the selection of the previous one, which would otherwise fire again.

The check with the cube

Grouping by set rolls up rarity and variant, so the cube answers at grouping_id 2 + 1 = 3. The cube has no card, and a view by card has no check.
