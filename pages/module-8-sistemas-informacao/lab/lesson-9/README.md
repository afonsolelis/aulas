# Lesson 9 · Lab: automated tests from ATAM scenarios

Module 8 · Information Systems · Inteli · Thursday, 03/12/2026

In this lesson each student tests the DataApp of the group alone, in class, with the method of the ATAM (Architecture Tradeoff Analysis Method). The business drivers give the quality attributes. The attributes are refined into a utility tree, and each leaf of the tree becomes a quality attribute scenario in six parts. Each scenario yields test cases, each test case becomes a pytest function marked with its scenario, and the results of the run are read back into the tree as risks, non-risks, sensitivity points and tradeoffs.

The professor applied the whole method to the package of Lesson 7, in `tcg_dataapp/` (version 0.3.0). A seventh step puts the suite in a pipeline of the GitLab of Inteli (git.inteli.edu.br), so that every push and every merge request runs it, and a daily schedule runs the DataApp on the real data. Its `docs/` folder holds the six documents of the method and `docs/results.md` the two runs: the first against the package of Lesson 7, which failed 5 of 29 tests in three scenarios, and the second after the changes that close those risks.

`index.html` is the lab of the session in the browser: a simulated editor in which the agent receives the seven prompts, writes the files of `tcg_dataapp/` and runs them. Its panels show the utility tree with the result of each leaf, the report of each test run and three pipelines of `.gitlab-ci.yml` as GitLab presents them: the merge request in green, the same merge request after a commit that disables the gate of S04, and the daily schedule. Its data are in `lab-data.js`, generated by `build_lab_data.py` (see the docstring): both runs of pytest are real, and each job of the pipelines ran in Docker with the image, rules, stages, needs, artifacts and cache of `.gitlab-ci.yml`; the recording is of 12/11/2026.

## Steps

| Step | Prompt | Produces | Reference |
|---|---|---|---|
| 01 | `prompts/01_drivers_and_attributes.md` | `docs/business_drivers.md` | 5 drivers, 8 attributes |
| 02 | `prompts/02_utility_tree.md` | `docs/utility_tree.md`, `docs/scenarios.toml` | 14 leaves rated (importance, difficulty) |
| 03 | `prompts/03_scenarios.md` | the six parts of each scenario, `docs/scenarios.md` | source, stimulus, artifact, environment, response, measure |
| 04 | `prompts/04_test_cases.md` | `docs/test_cases.md`, `docs/contracts/` | 20 test cases, each traced to one scenario |
| 05 | `prompts/05_implement_and_run.md` | `tests/scenarios/`, the plugin, `out/junit.xml` | 29 tests; first run 24 passed, 5 failed |
| 06 | `prompts/06_results_into_the_tree.md` | `docs/results.md`, `docs/traceability.md` | 3 risks closed, 2 open; second run 29 passed |
| 07 | `prompts/07_gitlab_pipeline.md` | `.gitlab-ci.yml`, the merge request, the schedule | 9 + 20 tests per pipeline; a red pipeline blocks the merge |

## The graded activity

The in-class graded activity of this session is the application of the six steps to the DataApp of the group, done by each student alone during the session. Its statement is the DAG and Testing Activity on Adalove: each student works on a branch `graded-activity/student-name` with a Prefect pipeline (Lesson 8) and the tests derived in the six steps, documents the implementation and the testing approach in a pull request and submits only the link by Friday, 04/12/2026. The criteria are those listed in the activity on Adalove. On git.inteli.edu.br the pull request is a merge request, and the pipeline of step 07 runs the tests of the branch on each push and shows their report in it.
