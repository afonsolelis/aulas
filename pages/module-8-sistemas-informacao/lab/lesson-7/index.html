The DataApp in a simulated editor

This page reproduces, in the browser, the session in which a coding agent builds the package tcg-dataapp. Each prompt is sent to the agent, which writes the files of the reference package and runs them in the terminal. The panels below the editor show the requests to the TCGplayer API, the rows that enter db_ingestion, the objects of the gold layer and the twelve tasks of the pipeline. The fifth step adds what the package still needs in order to run every day without anyone at the keyboard. Nothing runs here: the code is the code of the repository, the data are samples of a DuckDB file built by the package and the terminal shows output recorded on 12/11/2026.

What is real and what is simulated

The files that appear in the editor are the files of lab/lesson-7/tcg_dataapp/, except cli.py and README.md of step 01, which are the first versions that steps 04 and 05 replace. The answers of the API, the rows of db_ingestion and the samples of the gold layer come from a capture made by the package itself on 12/11/2026, and the output of the terminal was recorded on the same day. The agent, its messages and the timing are a staging of the session.

How to use it in class

  • Send each prompt and stop at the end of the step to compare the files with the review checklist of the slides.
  • Open the panels Network and db_ingestion during step 02 and Gold and Trace one card during step 03.
  • In step 05, the icon ⚙ shows the nine conditions for a run without anyone and which file meets each one.

Doing it for real

The README of lab/lesson-7/ lists the commands. In a new folder, the five prompts of prompts/ are pasted into the coding agent in this order; the reference package installs with pip install -e '.[dev]', runs with tcg-dataapp run in about 40 s and passes its 9 tests without network.
